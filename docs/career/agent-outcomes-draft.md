# Draft: outcomes for the Rocketlane AI agents (v2)

Status: DRAFT, not on the site. Figures below are Inbaraj's own estimates and feedback, given verbally.
Rules: use "~" and "estimated" for estimates; do not turn them into precise claims; never describe the Nitro agents as manual-to-automated (people were already using Claude separately).

## Facts provided by Inbaraj

**Atlas**
- Adoption: roughly 60-65% of the PS team, on average, today.
- Usage: about 10 queries per person per week.
- Usefulness: 70-80% of queries are useful to users (from overall feedback).
- Benefit: shortens the time spent reaching another implementation team member to get an answer; people can find it themselves.

**Nitro agents (handover, kickoff deck, workshop planner, solution design, UAT, form-to-Sheets)**
- Before: people already used Claude to generate these. Not manual-to-automated.
- Why Nitro: the data is already in the Rocketlane project (documents, meetings, meeting transcripts uploaded from Avoma), so no extra connections to Avoma or other sources are needed to gather context.
- Time: an estimated 20-30% reduction in time.
- Output quality: more legible, because it is built from data consolidated for that customer's project.
- Standardisation: everyone had a loose template; the agents give consistent formatting, so outputs are more repeatable.

## Proposed card: "Nitro · Agents the team runs on"

Keep the six agent bullets as they are, then add three outcome bullets:

- **Context built in:** Agents run inside the Rocketlane project, where documents, meetings, and call transcripts already live, so there is no need to pull data from Avoma and other sources before generating.
- **Time saved:** An estimated 20-30% reduction in time per deliverable.
- **Consistent output:** Replaced individually maintained templates with standardised formats, so outputs are clearer and repeatable across projects and implementation managers.

## Proposed Atlas card: add one bullet

- **Adoption & Impact:** About 60-65% of the PS team uses Atlas, averaging roughly 10 queries per person per week, with 70-80% of queries reported useful. People find answers themselves instead of tracking down a colleague.
